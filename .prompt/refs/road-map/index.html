Architecture

One schema, three runtime surfaces.

Valve owns the transition from caller memory to a copied runtime schema. Parsing, diagnostics, and help all consume that normalized model, so consumers do not duplicate option relationships or syntax descriptions.

Current signal

The core is stable. The edges are explicit.

The parser already covers typed long and short forms, boolean extensions, dotted names, one nested command level, generated help, and declarative constraints. Remaining work is mostly grammar expansion and operand state.

complete

Schema-driven core

Validation, copied ownership, typed values, caller targets, repeat arrays, KV values, and diagnostics.

Valve extension

Rich help surface

Targeted help, dotted groups, inferred signatures, toggles, and relationship annotations.

next pressure

Operands and unowned --

The behavior flag, storage, and accessors remain missing. A scoped command option now captures an opaque tail; the no-owner path still ignores it.
