03 · option relationships

Constraints live in the schema.

Valve models three presence-based relationships. Required is unconditional. Requires is directed and conditional. Conflicts is undirected. Runtime and generated help read the same Valve-owned edge tables.

post-parse order 
1. .required
2. .requires
3. .conflicts

reserved behavior returns before enforcement

Relationship model

Three semantics, no hidden reciprocity.

Presence means the user supplied the option. An explicitly supplied false boolean is still present for both requirements and conflicts.

complete

.required = true

The option must appear whenever its command scope is active. No target table is involved.

directed

A .requires B

If A appears, B must appear. B alone is valid. One source may require any number of targets.

undirected

A .conflicts B

A and B cannot appear together. One declaration annotates and enforces both directions.

Truth table

Directed means exactly one invalid state.

For A requires B, only A-present and B-absent is invalid. Reverse edges and cycles are legal because each declaration retains its direction.

A present B present Result Reason
no no valid The source is absent, so the edge is inactive.
no yes valid Requirements do not imply reciprocity.
yes yes valid The target satisfies the active edge.
yes no error VL_ERROR_UNSATISFIED_REQUIREMENT at A's argv index.

Ownership flow

Cross-references cross a lifetime boundary.

Public tables point at caller-owned vl_option_t objects during creation. Valve validates exact identity, maps each endpoint to its copied option, then stores normalized private edges.

01 Caller pointers

.requires and .conflicts reference declared options.

02 Validate

Check table shape, exact identity, visibility, self-reference, and duplicates.

03 Map

Resolve source and target against copied global, verb, and sub-verb options.

04 Store edges

Keep direction for requirements and normalize either order for conflicts.

05 Consume

Runtime checks and help annotations use only Valve-owned identities.

Scope matrix

A target must be visible to its source.

Local sources may reference upward to owning or global options. They cannot reference downward or sideways into a scope that is not always active with them.

Source scope Target scope Valid Reason
globalglobalyesBoth are always visible.
globalverb or sub-verbnoThe target is not always active.
verbsame verb or globalyesThe target is visible in the active chain.
verbsub-verbnoThe source can appear without that child scope.
sub-verbsame sub-verb, owner, or globalyesAll are active together.
localsibling scopenoSibling commands cannot be active together.

Deliberate boundary

Structural validation is not a solver.

Valve rejects malformed relation tables, but it does not prove that every combination of required, requires, and conflicts is satisfiable.

out of scope

Predicate-based requirements, one-of requirements, value-dependent edges, callback conditions, and full graph satisfiability remain separate future features rather than hidden behavior in the first relationship model.
