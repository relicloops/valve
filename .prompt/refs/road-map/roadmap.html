05 · implementation road-map

Finish the parser by pressure surface.

Expense and priority are recorded separately. Operands are the largest missing capability; schema-owned command tails now cover the executable-forwarding case after --. Smaller syntax additions should follow explicit ambiguity policies instead of accidental parser branches.

road-map rule

Decide the grammar before expanding it.

Each phase begins with a public contract, continues through owned runtime state and generated help, and ends at errors and lifecycle verification.

Status today

A dated capability matrix.

This table separates complete core contracts, deliberate Valve extensions, and missing parser surfaces. It reflects the implementation on 2026-09-02.

Long inline / separate mode complete Both forms exist across global assignment configurations. One executable cannot accept both at once.
Short inline / separate mode complete Both forms exist across global assignment configurations. One executable cannot accept both at once.
Long joined missing The whole token is treated as one exact long name. Prefix and ambiguity policy, parsing, errors, and help.
Short joined missing Characters after a short option are rejected. Joined value parsing and cluster coordination.
Short stacking missing -abc is not expanded. Cluster lexer, per-member errors, duplicates, and final value rule.
Bare booleans complete extension Bare means true; inline true and false literals are accepted. General optional option-arguments remain unsupported.
Enable / disable complete extension Both prefixes map to one toggle option. None.
Dotted options complete extension Exact matching, typed targets, target population, grouped and targeted help. None.
Targeted help complete extension Exact options, command paths, groups, and custom joined targets. Only a future standardization policy, if desired.
Operands declared only Ordinary positional tokens are rejected. Storage, accessors, lifecycle, collection, help, and behavior wiring.

Required options complete Active-chain enforcement plus automatic help. None.
Conflicts complete Many-option, undirected, presence-based edges and help. Full satisfiability analysis is intentionally absent.
Conditional requirements complete Many-option directed edges with forward and reverse help. Predicates and one-of requirements are outside the contract.
Inferred help complete Syntax comes from type, value, target, and assignment. .usage remains optional supplementary guidance.

Expense order

Largest parser change to smallest.

This order measures architectural reach. It does not require delivery in descending expense; low-cost policy additions may reasonably ship between larger phases.

rank 01 · very high

Operands and general --

missing

New public query surface, owned result storage, repeated-parse lifecycle, trailing positional collection, separate-value disambiguation, unowned-tail policy, errors, and help notation. Command forwarding is already complete.

rank 02 · high

Short stacking

missing

Add a per-character cluster parser, resolve every member in active scope, attribute duplicates and errors to one argv index, and allow only a value-taking final member.

rank 03 · high

Long joined values

missing

Define exact-match precedence, longest-prefix behavior, schema ambiguity, empty joined values, boolean handling, dotted names, diagnostics, and generated syntax.

rank 04 · medium

Short joined values

missing

The one-character name makes splitting easy, but the contract must still distinguish a joined value from a future short-option cluster.

rank 05 · low

Inline and separate together

missing

Extend the assignment enum or policy, accept both existing parse branches, validate the new mode, and display both accepted signatures in help.

Recommended delivery

Correctness first, then grammar breadth.

Expense alone should not dictate sequence. Command forwarding is complete; later phases can be chosen according to consumer demand.

phase A · correctness

Operands and unowned --

Implement the declared behavior flag and decide whether an unowned tail is collected or rejected.

phase B · low-risk reach

Combined assignment

Reuse proven inline and separate branches behind one explicit policy.

phase C · short grammar

Joined plus clusters

Design short joined and stacking together so the token split is coherent.

phase D · long grammar

Long joined policy

Ship only after ambiguity and exact-name precedence are part of the public contract.

phase E · command contract

Depth decision

Either reject deeper trees at creation or replace the two active pointers with a path.

phase F · optional graph work

Constraint solver boundary

Keep predicates, one-of semantics, and satisfiability separate unless consumers require them.

Acceptance gates

Every feature crosses the same surfaces.

A parser feature is not complete when one token branch works. It is complete when schema, lifecycle, errors, help, and repeated parsing agree.

contract gate
  • Public schema or behavior is explicit and documented.
  • Ambiguity and precedence rules are deterministic.
  • Invalid declarations fail during vl_create().
  • Reserved tokens retain their precedence contract.
runtime gate
  • Owned state clears on repeated parse and destroy.
  • Errors retain argv index, stable key, code, and message.
  • Inferred help displays every accepted spelling.
  • Global, verb, and sub-verb scopes behave consistently.
