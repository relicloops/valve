01 · runtime pipeline

From argv to typed state.

Valve separates schema construction from repeated parsing. Creation validates and copies caller declarations. Parsing selects command scope, intercepts reserved behavior, assigns typed values, and checks relationships.

runtime invariant

Caller pointers do not drive parsing.

After vl_create(), options, verbs, strings, conflicts, and requirements live in Valve-owned storage. Runtime checks use copied option identity and parsed-result presence.

Lifecycle

Five stages, one ownership boundary.

The same valve_t can parse more than once. Each parse clears prior results and errors while retaining the copied schema.

01 Declare

The caller describes metadata, globals, verbs, options, targets, and relationships.

02 Create

vl_create() validates the schema, copies it, and maps relation edges.

03 Parse

vl_parse() resolves scope and converts accepted tokens into typed values.

04 Query

Consumers inspect results, errors, active command names, or populated targets.

05 Destroy

vl_destroy() clears relation edges before copied options and verbs.

Decision flow

How one token moves through the parser.

Command tokens are consumed first. Every later token passes reserved-token interception before long, short, or positional classification.

command tail

A scoped VL_OPTION_VALUE_COMMAND receives the opaque, NULL-terminated tail after -- as a borrowed view. General operands and the policy for an unowned tail remain future work.

Command scope

Unlimited siblings, fixed depth.

Counts use size_t or null-terminated tables, so sibling quantity is memory-bound. Runtime state stores only one active verb and one active sub-verb.

runtime complete

Lookup precedence

Active sub-verb options win, followed by owning verb options, then global options.

schema mismatch

Recursive declarations

Validation and copying recurse deeper even though parsing and help stop at one sub-verb level.

Value routing

Syntax, value kind, and target are separate.

Option type chooses accepted spelling. Value kind chooses conversion. Target chooses where a converted value is copied. Dot notation uses its target to infer the scalar kind.
